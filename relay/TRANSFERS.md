# Private package transfers

`POST /v5/transfer` uses the existing link capability in Authorization; `/v4/transfer` remains for plain legacy transfers. Both sessions must still be linked. No public package URLs, directory listing, identity lookup or bearer values in logs. Server character identity is not authenticated; use trusted partners.

State machine: offer → recipient accept → sender sequential upload → hash verified → recipient download → client installation and activation confirmed → complete/delete. Reject/cancel, link expiry and TTL remove data. Sender cannot accept or download; outsiders cannot address a transfer by ID. Archive validation happens on the recipient before extracting and on sender before offering. Server treats bytes as opaque and checks SHA-256, bounds and offsets, never extracts them.

Storage is intentionally ephemeral memory, separate from the report SQLite database. Capacity is reserved at offer time: 128 MiB/package, 128 MiB total, 32 offers, 256 KiB chunks. A full-size package reserves all transfer capacity. One transfer per participant, 30-second sender offer cooldown. TTL 600 seconds, pruned during operations and every 30 seconds while idle. Process restart drops all offers and bytes. No backups contain packages. Download/delete completion cannot prove deletion from the recipient's own computer.

Deploy transfers.py with server.py, links.py and reports.py, and update Caddy's separate /v4/transfer and /v5/transfer request limit to 360 KB. Existing pair endpoints remain at 2 KB. Back up previous service files first; validate Caddy config before reload. Restarting the relay interrupts current pairs. Do not expose port 8765 publicly. Publish matching release SOURCE.zip at /opt/emoteshelf-relay/public/source.zip for the AGPL source offer; this public archive must never contain diagnostics, secrets or user packages.

Tests: `python -B -m unittest discover -s relay -p 'test_*.py'`. Client archive tests run in tests/PoseSlotTests.csproj. Full game-side import, collection-specific activation and rollback behavior must be tested against the installed Penumbra version before public release.

Optional `launch` is an immutable string of up to 8,192 characters describing a playback selection. It is returned to both participants and held only for the transfer lifetime, not written to reports. Clients validate its bounded JSON fields and bind acceptance to its exact value. It never grants arbitrary command execution: the receiving client resolves the emote against its own catalog and the imported mod. `complete` confirms install/activation, not successful animation playback.

V5 paired metadata includes opaque PairId, Family, SenderCommand and SenderRole hashes. Both peers must advertise v5 before such an offer. Recipient completion, after local role validation, creates an accepted launch offer with these identifiers; both clients still pass ordinary preparation/readiness barriers. Package receipt alone never schedules playback. Shared restart requires both peers to have finished the same accepted launch, a live unchanged link, no active launch and a 30-minute replay lifetime; clients additionally check their locally remembered role and current emote.
