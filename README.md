# Emote Shelf

Emote Shelf is a Dalamud plugin for playing emotes from different Penumbra mods without changing mod priorities by hand. It requires Penumbra.

Open it with `/eshelf` or `/es`. On **Emotes**, select a mod in the left pane; its emotes and variants appear on the right. Preview an option before adding it to the on-screen icon panel. Each icon saves its own Penumbra option selection and stays there after restarting the game. Variant bookmarks include both the mod and option-group names so similarly named options remain distinguishable. Click an icon to play; Ctrl+Shift+click removes it. Hide unwanted mods from the browser and restore them under **Settings → Hidden mods**.

Folders on the left are local visual categories. Select a folder and use **+** to create a child; choose **Create at root** for a top-level folder. Drag mods or folders onto another folder (or Unfiled for the root). Renaming/moving a folder preserves its subtree. Deleting a folder removes that branch's categories and returns its mods to Unfiled; it never deletes mods. Collapsed branches persist. This never moves Penumbra files or changes Penumbra's categories.

Options are grouped dropdowns and multi-select checkboxes, including sound-only choices such as Guitar Solo's songs. Preview and Add to panel use the whole selected combination. New bookmarks snapshot these options; old bookmarks retain their saved choices. Right-click a panel icon to open its mod in the Emotes tab. The dark violet interface uses content-sized cards rather than clipped fixed-height panels.

Variants known not to match the character's drawn model are filtered using the game's `papLoadTable.plt` redirections (format reference: [XIViewer](https://github.com/WorkingRobot/XIViewer/blob/main/viewer/src/character/stance.rs)). Unknown paths and non-animation options stay visible. **Show all variants** bypasses this conservative filter. This does not infer compatibility from option names or guarantee that every mod is correct for a body replacement.

Use **Panel** to change the icon grid, icon size, opacity, and position lock. Drag the grip beside a saved emote, or drag icons on the overlay, to reorder them. Locking removes the panel background while leaving its icons in place. The panel has no close button; hide it in the plugin or with `/es hide`. `/es show` brings it back, and `/es scan` refreshes the mod list.

When you play an icon, Emote Shelf temporarily gives its mod priority above the collection's other enabled mods, asks Penumbra to redraw your character, and starts the game emote. Before sending the command it checks both the temporary option settings and the effective animation file paths resolved by Penumbra; it refuses to play when another mod still owns a required file. The temporary selection remains until you play another icon, clear it in Settings, or unload the plugin. It does not change permanent Penumbra priorities.

For `/groundsit` replacements, the plugin reads `j_poseNN` filenames; standing-idle replacements use `poseNN`. Slot numbers are displayed without adding one. Switching between ground-sit replacements keeps the character seated. Leaving ground sit for a different kind of emote still stands up first. A previous looping emote must finish or be stopped before standing idle is available.

Manual pose selection is the default, also for users upgrading from 0.2.9.0. After launching a pose bookmark its panel icon becomes **Change pose** (or **↻** if the game icon is unavailable): each click sends exactly one `/cpose`, without reapplying settings or redrawing. Only the tooltip shows the reported and target slots; there is no footer or Done button. The icon restores automatically when the game reports the target. Starting another bookmark also exits this mode. Unknown telemetry is shown as `?`; it is never treated as confirmed. Slot telemetry is advisory, not proof of the visible animation.

Settings offers **Automatic pose selection (experimental, not fully tested)**, disabled by default. Disabling it cancels queued cycling and prevents saved-slot writes and unsolicited `/cpose` steps. Pose preparation follows the sequence examined in [Synastry](https://github.com/ShaalaXIV/Synastry/blob/main/EmoteLink/Plugin.cs): allow 300 ms for mod settings, then either refresh the active pose and wait 150 ms, or set the initial ground-sit slot immediately before `/groundsit` and wait 500 ms. Active poses are not reseated and do not wait for the normal-emote redraw acknowledgement. Cycling uses 100 ms between checks, with at most eight attempts. These are scheduling intervals, not a guarantee that the game finishes an animation transition in 100 ms. The previous active-pose SelectedPoses write technique was removed because it can produce misleading CPoseState feedback. Emote Shelf does not yet implement Synastry's separate carrier-emote mechanism for locked emotes.

Selected settings and mod ownership are checked, but exact physical filenames are not enforced: Penumbra may legitimately override animation files through higher-priority groups such as lip sync. Locked emotes are still blocked. Song selection and DefaultData discovery are fixed, but intermittent music loss when switching between already-playing emotes remains under investigation. Build and parser regression tests do not replace live-game validation of playback and layout.

Unrecognized animation mods are tucked away under **Settings → Unrecognized mods**. Many replace combat files rather than a directly playable emote, so you can usually ignore them. `/cpose3` is not a game command. A manual bookmark is allowed only for a real game emote command.

The interface supports Russian, English, Japanese, German, and French. The source is built with the Dalamud SDK and `Penumbra.Api.dll`.

## Experimental pair launch (0.3.2.0)

Both players need **Lightless Sync**, already synchronizing with each other, and Emote Shelf 0.3.2.0. Enable **Settings → Pair launch — experimental**. Right-click a nearby player and select **Emote Shelf: invite partner**. The other player receives a movable **Accept / Decline** window; accepting only selects a partner, never starts playback or movement. One partner at a time; invitations expire after 30 seconds and cannot replace a current partner. Disconnect through Settings or the partner's context menu. Logout, disabling pair mode, unloading Lightless or losing the relay ends the connection. Pair mode is off by default; enabling it while logged in with Lightless starts an ephemeral relay inbox, even when no launch is pending. Solo playback does not require Lightless.

Drag the invitation window by its title to save its position. **Settings → Preview / position notification** shows a sample without needing a real invitation; **Reset position** returns it to the upper-center area. Position is saved separately from the icon panel. No persistent partner or bearer token is saved to disk.

Once connected, stand still within two yalms on the same level. Each selects their own role/options of the same mod and clicks **Pair**, or Shift-clicks a panel bookmark. Keeping a target is no longer required. No Emote Shelf room, party or code is needed. Matching currently uses the normalized mod display name, so both must have the same name and should use the same mod version. Different commands and option combinations within that mod are allowed. Each launch still requires both players to click; the connection itself is not consent to playback or movement.

Lightless handles mod/appearance distribution; Emote Shelf handles local choices, approach and the shared timer. The client requires loaded `LightlessSync` and checks the selected actor via `LightlessSync.GetHandledAddresses` (verified against installed 3.3.0.0). Missing IPC/actor or unloading Lightless stops pair launch. This API reports handled actors, **not completed downloads for a particular animation**. Wait for Lightless to finish synchronization, especially after changing roles or using an animation for the first time. Emote Shelf does not access Lightless accounts, tokens or pairing configuration. If self and target still share a Penumbra collection, the progress window warns that applying your options may affect both characters.

**Allow a short approach and alignment** is a separate, default-off opt-in on each client. Only if both allow it does one character approach the other and match facing; the other remains the anchor. The destination comes from the local game's current target, not network coordinates. This uses normal movement input, not direct position writes or teleporting. A blocked approach, movement input or a 2.5-second timeout cancels the operation. It does not apply skeleton, body-size or per-role offset corrections. The approach mechanism was researched in [Synastry's MovementService](https://github.com/ShaalaXIV/Synastry/blob/main/EmoteLink/MovementService.cs); Synastry and Simple Heels are not dependencies. Game updates can invalidate the movement hook; failure disables that attempt rather than bypassing the range checks.

Both clients prepare their own Penumbra settings before the relay schedules a shared command start. A separate progress window provides Cancel; closing it cancels pending readiness. Another local playback, changing zone, movement, combat/casting/mounting, changed prepared files/settings, lost partner/connection or an expired start also cancels. No incoming message can choose your role, supply a game command or set movement coordinates. For sit/idle, experimental automatic pose selection must also be on; manual mode is never silently overridden.

This is a best-effort shared **command start**, not frame-accurate animation synchronization. Pose entry/cycling, asset loading, remote game updates, asymmetric latency and a last-moment disconnect can still produce different visible phases. In particular, sit/idle and modded music need two-player live testing. Do not use this build as evidence those issues are solved. Ordinary local playback remains available without the pair service.

### Relay and privacy

The HTTPS relay is `https://anarchyclan.ru`. It sees IP addresses, hashes of names/home worlds/current worlds/territories, a mod-name hash and the alignment opt-in. The inbox uses a stable name/home-world hash; a launch also includes current world/territory. No mod files, option settings, chat or commands are uploaded. Hashes are deterministic and guessable; they are **not anonymity or authenticated proof of game identity**. Only accept an expected invitation from a trusted partner. The relay cannot verify FFXIV identity: a displayed locally resolved name is not proof of who sent a request. An attacker who can guess identifiers could interfere with availability/readiness, though the client still only executes its explicitly selected local action.

Readiness expires after 60 seconds, with short heartbeat leases. Session capabilities travel in Authorization headers, not URLs. A new request cannot replace an existing readiness by claiming its character hash. The service binds loopback behind Caddy, runs as an unprivileged systemd dynamic user, limits request sizes/workers/session count/rate and does not log bearer tokens or identifiers. It keeps session data in memory only; restarting it cancels outstanding pairs.

Run `python3 -B -m unittest -v` in `relay/` for store and real HTTP tests, including invitation consent, stale nonces, expiry, cooldown, single-partner enforcement and disconnect. The standalone C# regression project tests two clients, preparation barriers, timing, revocation, and rejection of unsolicited starts. Passing `--pair-relay-test` exercises two synthetic launch clients against HTTPS; `--link-relay-test` tests invitation/accept/disconnect. Neither sends real game-character data nor tests game playback, notification layout or movement.
